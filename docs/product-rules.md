# Product rules and where they are enforced

Every rule exists twice on purpose: in Postgres (the authority) and in `@org/domain` (for UI decisions and tests). When you change one, change the other and its tests.

| Rule                                                                                                                        | Postgres                                                                   | `@org/domain`                                                                                                                                  | UI                                          |
| --------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------- |
| Roles: consumer / business / admin; admin never self-assigned; role mirrored into JWT                                       | `handle_new_user`, `sync_role_to_auth`, `profiles_update` policy           | `roleFromClaims` (in `@org/supabase`)                                                                                                          | `proxy.ts` gates                            |
| Business verification is admin-only; owners cannot change `verification_status`                                             | `protect_business_verification` trigger + `is_privileged()`                | `verificationStatusLabels`                                                                                                                     | `/admin`, `/pendiente`, `(verified)` layout |
| A business is public only when **verified and ≥ 3 live coupons**                                                            | view `businesses_public`                                                   | `missingActiveCoupons`, `MIN_ACTIVE_COUPONS = 3`                                                                                               | banner on `/cupones`                        |
| A verified business cannot deactivate/delete a live coupon if fewer than 3 would remain                                     | `coupons_min_active` trigger, error `MIN_ACTIVE_COUPONS` with Spanish hint | `canDeactivateCoupon(liveCount, isVerified)`                                                                                                   | toggle disabled at 3; error toast from hint |
| Coupon "live" = active and inside `valid_from`/`valid_until`                                                                | `coupon_is_live(c)`                                                        | `isCouponLive`                                                                                                                                 | list shows "Fuera de su periodo"            |
| Best-discount score 0..100: percentage as-is, fixed = value / 40,000 COP × 100 (cap 100), bogo 50, other 0                  | `coupon_score`                                                             | `couponScore`                                                                                                                                  | sort "Los mejores descuentos" (Phase 4)     |
| Subscription entitlement: trialing → trial end; active → period end; past_due → period end + 5 days; canceled → period end  | `subscription_access_until(s)`                                             | `subscriptionAccessUntil`, `isEntitled`, `PAST_DUE_GRACE_DAYS`, `TRIAL_DAYS`, `MAX_CHARGE_ATTEMPTS`, `CHARGE_RETRY_DAYS`                       | subscription gate (Phase 6)                 |
| QR token `dm1.<consumer>.<coupon>.<exp>.<jti>.<hmac>`; 90 s TTL, refreshed every 60 s; replay blocked by unique `token_jti` | `issue_coupon_token`, `verify_coupon_token` (Vault `qr_token_secret`)      | `parseCouponToken`, `couponTokenSecondsLeft`, `redemptionReasonMessages`                                                                       | Phase 5 screens                             |
| Categories: restaurants, beverages, desserts, retail                                                                        | enum `business_category`                                                   | `CATEGORIES`, `categoryLabel`                                                                                                                  | chips (Phase 4)                             |
| Default map center Bogotá (4.711, -74.0721), 10 km radius when geolocation is denied                                        | `nearby_businesses(p_lat, p_lng, p_category, p_radius_m, p_sort, p_limit)` | `DEFAULT_MAP_CENTER`, `DEFAULT_SEARCH_RADIUS_M`                                                                                                | Phase 4                                     |
| Uploads: PNG/JPG/WebP ≤ 2 MB under `<business_id>/` in `logos` or `coupon-images`                                           | storage policies (owner folder)                                            | `LOGO_MIME_TYPES`, `LOGO_MAX_BYTES`                                                                                                            | onboarding, coupon editor                   |
| Input validation                                                                                                            | CHECK constraints (title 3–60, percentage 1–100, fixed > 0)                | zod: `loginSchema`, `consumerSignupSchema`, `businessProfileSchema`, `branchSchema`, `onboardingSchema`, `couponSchema`, `profileUpdateSchema` | forms                                       |

Decisions that changed during implementation are logged with dates at the bottom of [mvp-plan.md](mvp-plan.md#decision-log).
