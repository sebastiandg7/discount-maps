# Product rules and where they are enforced

Every rule exists twice on purpose: in Postgres (the authority) and in `@org/domain` (for UI decisions and tests). When you change one, change the other and its tests.

| Rule                                                                                                                                                                                                                                        | Postgres                                                                                                                                         | `@org/domain`                                                                                                                                  | UI                                                                           |
| ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------- |
| Roles: consumer / business / admin; admin never self-assigned; role mirrored into JWT                                                                                                                                                       | `handle_new_user`, `sync_role_to_auth`, `profiles_update` policy                                                                                 | `roleFromClaims` (in `@org/supabase`)                                                                                                          | `proxy.ts` gates                                                             |
| Business verification is admin-only; owners cannot change `verification_status`                                                                                                                                                             | `protect_business_verification` trigger + `is_privileged()`                                                                                      | `verificationStatusLabels`                                                                                                                     | `/admin`, `/pendiente`, `(verified)` layout                                  |
| A business is public only when **verified and ≥ 3 live coupons**                                                                                                                                                                            | view `businesses_public`                                                                                                                         | `missingActiveCoupons`, `MIN_ACTIVE_COUPONS = 3`                                                                                               | banner on `/cupones`                                                         |
| A verified business cannot deactivate/delete a live coupon if fewer than 3 would remain                                                                                                                                                     | `coupons_min_active` trigger, error `MIN_ACTIVE_COUPONS` with Spanish hint                                                                       | `canDeactivateCoupon(liveCount, isVerified)`                                                                                                   | toggle disabled at 3; error toast from hint                                  |
| Coupon "live" = active and inside `valid_from`/`valid_until`                                                                                                                                                                                | `coupon_is_live(c)`                                                                                                                              | `isCouponLive`                                                                                                                                 | list shows "Fuera de su periodo"                                             |
| Best-discount score 0..100: percentage as-is, fixed = value / 40,000 COP × 100 (cap 100), bogo 50, other 0                                                                                                                                  | `coupon_score`                                                                                                                                   | `couponScore`                                                                                                                                  | sort toggle "Los mejores descuentos" on `/mapas` (`p_sort = 'discount'`)     |
| Subscription entitlement: trialing → trial end; active → period end; past_due → period end + 5 days; canceled → period end                                                                                                                  | `subscription_access_until(s)`                                                                                                                   | `subscriptionAccessUntil`, `isEntitled`, `PAST_DUE_GRACE_DAYS`, `TRIAL_DAYS`, `MAX_CHARGE_ATTEMPTS`, `CHARGE_RETRY_DAYS`                       | coupon detail shows "Tu suscripción no está activa" instead of a QR          |
| Trial gate: no `subscriptions` row → card capture first; the row is created only after a Wompi payment source exists                                                                                                                        | `subscriptions` written by service role only (RLS)                                                                                               | `TRIAL_DAYS = 7`                                                                                                                               | `(app)/layout.tsx` → `/suscripcion/tarjeta`; `startTrialAction`              |
| Billing: charge when `next_charge_at <= now` and attempts < 3; APPROVED → active, +1 month, attempts 0; failure → past_due, retry in 2 days, canceled after the 3rd                                                                         | `payments` (unique `reference`), `wompi_events` (checksum PK), cron `billing-run-hourly`                                                         | `isChargeDue`, `planCharge`, `applyPaymentOutcome`, `paymentReference`, `addMonths`                                                            | `/api/billing/run`, `/api/wompi/webhook` (people-web)                        |
| Cancel: no more charges, access until `subscription_access_until` (period end / trial end). Update card: re-capture, swap source; past_due / expired-canceled → due now + immediate charge; canceled with time left → trialing/active again | `subscriptions` written by service role only; `subscription_access_until(s)` (canceled → period end)                                             | `cancelSubscription`, `applyNewPaymentSource`, `planCharge(s, now, priorPayments)`                                                             | `/cuenta` `SubscriptionCard`, `/cuenta/tarjeta` (`updateCardAction`)         |
| A business keeps at least one branch                                                                                                                                                                                                        | `branches_min_one` trigger, error `MIN_BRANCHES` with Spanish hint (privileged bypass)                                                           | `MIN_BRANCHES = 1`, `MIN_BRANCHES_ERROR`, `MAX_BRANCHES = 20`                                                                                  | merchant `/cuenta` "Quitar" disabled at 1; `AddBranchForm` hidden at 20      |
| Profile: name + optional phone editable by the owner; role never; email not self-service; password change = new password twice                                                                                                              | `profiles_update` policy (`role = app_role()`)                                                                                                   | `profileUpdateSchema`, `passwordChangeSchema`                                                                                                  | `ProfileForm`, `PasswordForm` on both `/cuenta` pages                        |
| Contact channels: Instagram, TikTok, email (WhatsApp pending)                                                                                                                                                                               | —                                                                                                                                                | `CONTACT_LINKS`                                                                                                                                | `ContactLinks` on both `/contacto` pages                                     |
| New coupon → push to followers with `notify = true`; only live coupons of verified businesses; endpoints the push service reports gone (404/410) are deleted                                                                                | `coupons_notify_followers` trigger → `net.http_post` (guarded by Vault secrets); `push_subscriptions` unique `endpoint`; `business_followers` PK | `dispatchPush`, `newCouponPayload` (people-web `src/lib/push-dispatch.ts`)                                                                     | `NotifyToggle` on `/negocios/[id]`; `/api/push/new-coupon`                   |
| QR token `dm1.<consumer>.<coupon>.<exp>.<jti>.<hmac>`; 90 s TTL, refreshed every 60 s; replay blocked by unique `token_jti`                                                                                                                 | `issue_coupon_token` (raises), `verify_coupon_token` (returns reason); Vault `qr_token_secret`                                                   | `parseCouponToken`, `couponTokenSecondsLeft`, `redemptionReasonMessages`, `issueTokenErrorMessages`                                            | `/negocios/[id]/cupones/[couponId]` (`CouponQr`) + `/verificar` (`Verifier`) |
| Categories: restaurants, beverages, desserts, retail                                                                                                                                                                                        | enum `business_category`                                                                                                                         | `CATEGORIES`, `categoryLabel`                                                                                                                  | `CategoryChips` on `/mapas`                                                  |
| Default map center Bogotá (4.711, -74.0721), 10 km radius when geolocation is denied                                                                                                                                                        | `nearby_businesses(p_lat, p_lng, p_category, p_radius_m, p_sort, p_limit)`                                                                       | `DEFAULT_MAP_CENTER`, `DEFAULT_SEARCH_RADIUS_M`; `useGeolocation` in `@org/maps`                                                               | "Ubicación no disponible · Usar mi ubicación" chip                           |
| Uploads: PNG/JPG/WebP ≤ 2 MB under `<business_id>/` in `logos` or `coupon-images`                                                                                                                                                           | storage policies (owner folder)                                                                                                                  | `LOGO_MIME_TYPES`, `LOGO_MAX_BYTES`                                                                                                            | onboarding, coupon editor                                                    |
| Input validation                                                                                                                                                                                                                            | CHECK constraints (title 3–60, percentage 1–100, fixed > 0)                                                                                      | zod: `loginSchema`, `consumerSignupSchema`, `businessProfileSchema`, `branchSchema`, `onboardingSchema`, `couponSchema`, `profileUpdateSchema` | forms                                                                        |

Decisions that changed during implementation are logged with dates at the bottom of [mvp-plan.md](mvp-plan.md#decision-log).
